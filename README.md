# 极地救援站 · 摩尔斯纸带复原

值班员录入受潮无线电纸带的**明暗游程**（按出现顺序）与**允许的整数单位时长范围**，
应用在整个序列上共同选择一个整数单位时长和各游程解释，复原受限字母表与词典下的呼救电文——
避免把局部最接近的点划误拼成不存在的呼号。

## 规则模型

- 纸带以**信号游程开始并结束**，明暗交替（游程总数为奇数）。
- 信号游程 → 点（1 单位）或划（3 单位）；空白游程 → 符内（1）、字母间隔（3）或词间隔（7）。
- 单位时长取 `[unitMin, unitMax]` 内的整数，全局唯一；解释自由、偏差不设上限，
  可行性只取决于“解释后的摩尔斯序列能否恰好译成词典中的词序列”。
- 多个可行复原的取舍次序：**总绝对时长偏差最小 → 单段最大偏差最小 →
  按游程顺序的解释编码字典序最小**（点/符内=0，划/字母=1，词=2），仍并列时取较小单位时长。
- **无解时**定位“最早无法落入任何有效词典前缀的游程”并给出原因（词典前缀 / 完整单词 /
  字母表 / 码长），绝不输出貌似完整的电文。
- 页面上草稿的**任何改动立即使已复原的电文失效**（结果与草稿指纹绑定，失效后需重新求解）。

## 页面

- 可编辑游程（逐段时长、追加/删除“空白+信号”）、单位范围、受限字母表、词典；
  含干净 / 受潮 / 无解三个预设样例。
- 结果区清楚呈现：每段解释（点/划/符内/字母/词间隔）、目标时长、逐段与**累计偏差**、
  **词界**（词间隔行与游程条标记）、电文单词分块、摩尔斯序列，以及无解时**未能译码的位置**
  （编辑器与游程条同步高亮）。

## 本地开发

```bash
npm ci
npm run dev        # 开发服务器
npm run test       # 单元测试（vitest）
npm run build      # 类型检查 + 生产构建
npm run smoke:core # 复原核心样例冒烟
```

## Docker 运行

```bash
WEB_PORT=8080 docker compose up --build
# 站点：http://localhost:8080  （健康检查：http://localhost:8080/health）
```

- `web` 服务：多阶段构建的 nginx 静态站点，暴露 `${WEB_PORT:-8080}:80`，
  内置 `/health` HTTP 健康端点，Compose 以健康检查确认可用。
- `verify` 一次性服务：待 `web` 健康后运行，依次报告
  **单元测试 → 生产构建 → 复原核心样例冒烟 → 健康端点冒烟**，
  总体结论体现在**退出码**（0=全部通过，非 0=失败）：

```bash
docker compose up --build --exit-code-from verify verify  # 查看 verify 结论
docker compose ps verify                                   # 或查看其退出码
```

## 目录结构

```
src/core/       与 UI 解耦的复原核心（morse / types / solve / samples）
src/components/ 游程编辑器、结果面板、游程条
tests/          vitest 单元测试（求解器 + 渲染冒烟）
scripts/        verify.sh、smoke-core.ts、healthcheck.mjs
Dockerfile      deps → build → web(nginx) / verify 多阶段
docker-compose.yml  web（WEB_PORT 暴露 + 健康检查）与 verify 一次性服务
```
